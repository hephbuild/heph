# In-place codegen (`codegen = "in_place"`)

A formatter that rewrites its **own, committed** source files — and a contrasting
`codegen = "copy"` target that emits a **generated, gitignored** file.

Run everything below from the `example/` workspace root (the dir with
`.hephconfig2`). `heph` ≈ `cargo run -q --` with `HEPH_CWD` pointing here.

## In-place: `//fmt:fmt`

`greeting.txt` and `note.txt` are tracked, lowercase source. The `fmt` target
"formats" them (here: uppercases) **in place**.

```
$ heph run //fmt:fmt
$ cat fmt/greeting.txt
HELLO WORLD
```

Three things make this work:

- **`codegen = "in_place"`** — heph writes the collected outputs back onto the
  source tree (write-if-changed, so an already-correct file's mtime is untouched).
- **`//@heph/introspect:outputs`** — an engine-baked magic dep. It expands, per
  declared output path, into an input that reads that path. So the target's
  *inputs are its outputs* ("format these files"), surfaced to the run script via
  `$SRC_SRC` / `$LIST_SRC_SRC`.
- **Fixed-point caching** — re-running over the already-formatted tree is a no-op
  **cache hit**, not a re-run:

  ```
  $ heph run //fmt:fmt        # second run
  ... cache 1 hit / 0 miss    # the formatter did NOT execute
  ```

### CI check: `--frozen`

Verify formatting without writing anything. Exits non-zero with a diff if a file
is not formatted:

```
$ heph run //fmt:fmt --frozen          # clean tree → passes
$ echo 'hello world' > fmt/greeting.txt
$ heph run //fmt:fmt --frozen          # dirty tree → fails
× target failed: //fmt:fmt
╰─▶ generated output differs from tree
  ╭─[diff]
  │ --- a/fmt/greeting.txt
  │ +++ b/fmt/greeting.txt
  │ @@ -1 +1 @@
  │ -hello world
  │ +HELLO WORLD
  ╰────
```

## Copy (generated): `//fmt:generated`

`codegen = "copy"` writes a generated file to the tree, and a later `glob()` /
`file()` excludes it — it is a build output, not source. Consumers depend on the
target (`//fmt:generated`), not on the file.

**Nothing is written onto the file to mark it.** heph keeps the claim beside the
file instead, in two places:

- **`.heph3/codegen-claims`** — a heph-owned ledger, written by the write-back in
  the same operation that puts the file on disk. So a generated file is never on
  disk unclaimed, and no command has to be run first. This is the one that makes
  it work by default.
- **The heph-managed `.gitignore` section** — written by
  `heph tool gen-gitignore` from the *declared* output paths and checked by
  `heph validate`:

  ```
  # BEGIN heph-generated (managed by `heph tool gen-gitignore` — do not edit)
  # //fmt:generated
  /fmt/generated.txt
  # END heph-generated
  ```

  Being committed and declarative, it covers what the ledger cannot: a path
  that has not been generated yet, and a workspace whose `.heph3` was deleted
  while the generated files survived.

### Changing or removing a codegen target

Move a `copy` target's `out` and the old path is released the next time that
target generates — a target's claims are replaced wholesale, not accumulated.

**Delete** the target, though, and it never generates again, so nothing releases
its claims on its own. That matters: a claim with no target behind it keeps
hiding whatever is at that path, so a real source file you later add there is
invisible to every `glob()`. `heph tool gen-gitignore` reconciles both the ledger
and the `.gitignore` section against the targets that actually exist, reporting
what it released; `heph validate` fails when they disagree. (The generated file
itself is left in the tree — heph does not delete from your working tree.)

An earlier design stamped a `user.heph.codegen` extended attribute on the file.
The stamp landed at the right moment — when the file was created — but xattrs
live on the inode, and almost every tool rewrites a file by writing a temp and
renaming over it. A formatter, an editor save, or a `git checkout` erased it, and
the generated file quietly went back to looking like source.

```
$ heph run //fmt:generated
$ cat fmt/generated.txt
generated by //fmt:generated
```

## The distinction

| | `copy` | `in_place` |
|---|---|---|
| Meaning | generated artifact | tracked source, reformatted |
| Git | gitignored | committed |
| Globs | excluded (claimed as codegen) | visible (unclaimed) |
| Inputs | its own (e.g. a schema) | its outputs (`//@heph/introspect:outputs`) |
